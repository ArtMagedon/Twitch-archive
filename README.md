# Twitch Archive

Docker-сервис для мониторинга публичных Twitch-каналов и записи прямых эфиров в реальном времени. Управление каналами, архивом, накопителями и диагностикой доступно через веб-интерфейс.

## Возможности

- Мониторинг настраиваемого списка публичных Twitch-каналов через Streamlink Twitch plugin, без собственного Twitch Helix API клиента и без Client ID/Client Secret.
- Ручная проверка эфиров по кнопке обновления и периодическая проверка в фоне.
- Автоматический запуск Streamlink при обнаружении публичного эфира.
- Запись в качестве `best` в MPEG-TS (`.ts`).
- React + Vite frontend, FastAPI backend, SQLite.
- Docker Compose; данные и видео хранятся на хосте.
- Цветной вывод логов в stdout, ротация файлов журналов и журнал в веб-консоли с фильтрами по компонентам и уровню.
- Подробные карточки ошибок с исходным сообщением, traceback/stderr, временем, компонентом и идентификаторами записи/канала.
- Диагностическая страница с проверкой Streamlink, пробой конкретного канала, Chromium, SQLite, процессов записи и выбранного хранилища.
- Обнаружение смонтированных внешних дисков под каталогом `/media/miko`; выбор каталога `recordings` в корне диска.
- Защита от записи на системный диск, если выбранный внешний диск отключён.
- Нет автоматического удаления архива и программного лимита хранения.
- Восстановление состояния записей после аварийного перезапуска контейнера.

## Требования

- Docker Engine и Docker Compose plugin.
- Streamlink и Chromium (устанавливаются в Docker-образ автоматически).
- Достаточно свободного места на диске. При отсутствии автоочистки объём архива будет постоянно расти.

## Установка

1. Склонируйте репозиторий и перейдите в каталог проекта.
2. Создайте конфигурацию: `cp .env.example .env`.
3. Укажите UID/GID пользователя хоста в `PUID` и `PGID` (узнать их можно командами `id -u` и `id -g`). Это нужно, чтобы Chromium запускался не от root и сохранял sandbox.
4. Создайте каталоги данных: `mkdir -p data recordings`. Если они уже существуют и принадлежат root, исправьте владельца: `sudo chown -R $(id -u):$(id -g) data recordings`.
5. Проверьте, что внешний диск смонтирован под `/media/miko`, например `/media/miko/Seagate Drive`.
6. Запустите: `docker compose up -d --build`.
7. Откройте `http://SERVER_IP:8080`.

Для OAuth Redirect URL можно указать `http://localhost`: пользовательский OAuth-поток не используется. Сервис не запрашивает Twitch App Access Token и не обращается к Twitch Helix API самостоятельно. Streamlink использует собственный Twitch plugin и необходимый внутренний процесс получения потока. Когда Twitch требует Client Integrity token, Streamlink вычисляет его через изолированный Chromium-браузер. Контейнер запускает приложение от UID/GID хостового пользователя (переменные `PUID`/`PGID`), чтобы не отключать Chromium sandbox.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `POLL_INTERVAL_SECONDS` | Интервал проверки эфиров (минимум 15 секунд) | `45` |
| `STREAM_QUALITY` | Начальное качество записи при первом запуске, дальше используется значение из SQLite | `best` |
| `STREAM_CHECK_TIMEOUT_SECONDS` | Таймаут проверки канала через Streamlink | `25` |
| `LOG_LEVEL` | Минимальный уровень логирования backend | `INFO` |
| `TZ` | Часовой пояс контейнера | `Europe/Berlin` |

## Внешние диски

Внешний диск должен быть смонтирован средствами ОС хоста внутри каталога `/media/miko`, например `/media/miko/Seagate Drive`. В Compose этот каталог подключается внутрь контейнера по тому же абсолютному пути: `/media/miko:/media/miko`. Поэтому приложение и Streamlink используют одинаковый путь на хосте и внутри контейнера, а файлы физически записываются непосредственно на внешний накопитель. Для получения событий подключения вложенных файловых систем используется propagation `rslave`.

После подключения накопитель должен появиться в нижней панели интерфейса. При нажатии на значок показываются метка/имя, общий и занятый объём, свободное место, файловая система и точка монтирования. В разделе «Настройки» можно выбрать внешний диск. Файлы будут записываться в `recordings/` в корне выбранного раздела, например `/media/miko/Seagate Drive/recordings`.

Приложение не выполняет mount/umount и не получает `CAP_SYS_ADMIN`. Контейнеру требуются права записи в каталог `recordings` на выбранном диске. Если раздел отключён, приложение оставляет выбранное хранилище в настройках, показывает его как недоступное и не переключается автоматически на внутренний каталог. Это сделано, чтобы внезапное отключение накопителя не привело к незаметному заполнению системного диска.

## Логи и диагностика

В веб-интерфейсе откройте «Консоль» → «Логи». Поддерживаются фильтрация по нескольким компонентам и минимальному уровню логирования. Цвета: обычные сообщения — белые, успешные события — зелёные, предупреждения — жёлтые, ошибки — красные. Нажатие на предупреждение или ошибку открывает подробную карточку. Файловые журналы хранятся в `./data/logs/application.log`; применяется ротация (10 MiB × 5 файлов).

Для просмотра логов вне веб-интерфейса:
```bash
docker compose logs -f twitch-archive
tail -f ./data/logs/application.log
```

В разделе «Консоль» → «Диагностика» доступны проверка Streamlink, тест конкретного канала без записи видео, состояние Chromium, базы SQLite, мониторинга и активных процессов. API документация доступна по адресу `http://SERVER_IP:8080/docs`.

### Ошибка Streamlink с кодом 1

Код 1 сам по себе не определяет причину. В веб-консоли откройте соответствующую запись в архиве и посмотрите сохранённый stderr. В нём могут быть сообщения о недоступном потоке, ошибке плагина Twitch, сетевом сбое, отказе в доступе или проблеме с выходным файлом. В новой версии stderr читается непрерывно, поэтому вывод не должен блокировать процесс при заполнении pipe. После неуспешного запуска включается задержка повторной попытки с увеличением до 15 минут, чтобы не создавать множество пустых записей.

Проверка Streamlink в разделе диагностики выполняет только `streamlink --version`; она проверяет доступность бинарного файла, но не гарантирует доступность конкретного Twitch-эфира. Для выяснения причины конкретного кода 1 необходима карточка ошибки из раздела «Архив» или лог Streamlink из консоли.

## Хранение

- `./data/archive.db` — база SQLite.
- `./data/logs/application.log` — текущий файл логов; старые файлы ротируются.
- `./recordings/<channel>/<YYYY-MM-DD>/` — видео по умолчанию.
- При выборе внешнего диска: `<mountpoint>/recordings/<channel>/<YYYY-MM-DD>/`.

Записи не удаляются автоматически. Удаление записи из интерфейса удаляет соответствующий видеофайл, если он доступен. Удаление канала удаляет его метаданные и историю из SQLite, но оставляет видеофайлы на диске.

## Команды

```bash
docker compose up -d --build
docker compose logs -f twitch-archive
docker compose ps
docker compose down
```

`docker compose down` не удаляет каталоги `data` и `recordings`, так как они подключены как bind mounts.

## API

- `GET /api/health` — состояние приложения.
- `GET /api/status` — счётчики и состояние мониторинга.
- `GET /api/channels` — каналы и последние ошибки проверки.
- `POST /api/monitor/check` — немедленно проверить эфиры Twitch.
- `GET /api/logs` — события журнала; параметры `components`, `level`, `limit`, `after`.
- `GET /api/diagnostics` — расширенное диагностическое состояние.
- `POST /api/diagnostics/streamlink` — проверка исполняемого файла; `POST /api/diagnostics/streamlink/channel` — проверка конкретного канала без сохранения видео.
- `GET /api/storage` и `POST /api/storage` — список дисков и выбор места записи.

## Ограничения и правовые аспекты

Запись начинается после обнаружения трансляции очередным циклом мониторинга, поэтому фрагмент эфира до обнаружения не сохраняется. Сервис не восстанавливает пропущенные части, не скачивает скрытые или удалённые VOD, не обходит ограничения доступа и не получает доступ к приватным трансляциям. Используйте его только для публичного контента, на который у вас есть соответствующие права, соблюдая условия Twitch и применимое законодательство.

Для мониторинга не требуются Client ID и Client Secret. Streamlink может обращаться к сервисным endpoint Twitch через собственный plugin, но приложение не использует Twitch Helix API и не имеет собственного OAuth Client Credentials Flow.
