# Twitch Archive — no API

Docker-сервис для мониторинга публичных Twitch-каналов и записи прямых эфиров в реальном времени. Эта версия использует Streamlink для проверки доступности трансляций и записи. Twitch Helix API, Client ID и Client Secret не требуются.

## Возможности

- Мониторинг списка Twitch-каналов без регистрации приложения в Twitch Developer Console.
- Проверка доступности эфира через Twitch-плагин Streamlink.
- Автоматический запуск Streamlink для записи обнаруженного публичного эфира.
- Запись в выбранном качестве (по умолчанию `best`) в MPEG-TS (`.ts`).
- React + Vite frontend, FastAPI backend, SQLite.
- Docker Compose; данные и видео хранятся на хосте в `./data` и `./recordings`.
- Нет автоматического удаления архива и программного лимита хранения.
- Восстановление состояния записей после аварийного перезапуска контейнера.

## Требования

- Docker Engine и Docker Compose plugin.
- Достаточно свободного места на диске.

## Установка

1. Склонируйте репозиторий и перейдите в каталог проекта.
2. Создайте конфигурацию: `cp .env.example .env`.
3. При необходимости измените параметры в `.env`. Twitch Client ID и Client Secret не нужны.
4. Запустите: `docker compose up -d --build`.
5. Откройте `http://SERVER_IP:8080`.

## Как работает мониторинг

Для каждого включённого канала сервис запускает короткую проверку:

```bash
streamlink --json --loglevel error https://www.twitch.tv/CHANNEL
```

Если Streamlink обнаруживает доступный поток, сервис запускает отдельный процесс записи. Проверки выполняются последовательно, поэтому при большом количестве каналов полный цикл мониторинга может занимать заметное время.

Эта реализация не использует Helix API и не получает метаданные трансляции: название, категорию, количество зрителей и точное время начала. Поэтому часть этих полей в интерфейсе будет пустой. Статус эфира определяется по результату Streamlink.

У Streamlink могут меняться способы получения публичных потоков из-за изменений на стороне Twitch. Twitch может ограничивать доступ или требовать дополнительные параметры/авторизацию; эта версия не обходит такие ограничения. Если Twitch-плагин Streamlink перестанет обнаруживать трансляции, потребуется обновить Streamlink или изменить способ проверки.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `POLL_INTERVAL_SECONDS` | Интервал между циклами мониторинга (минимум 30 секунд) | `60` |
| `STREAM_CHECK_TIMEOUT_SECONDS` | Максимальное время одной проверки канала (минимум 10 секунд) | `25` |
| `STREAM_QUALITY` | Качество записи Streamlink | `best` |
| `TZ` | Часовой пояс контейнера | `Europe/Bucharest` |

## Хранение

- `./data/archive.db` — база SQLite.
- `./recordings/<channel>/<YYYY-MM-DD>/` — видеофайлы.

Записи не удаляются автоматически. Удаление записи из интерфейса удаляет соответствующий файл. Удаление канала удаляет его метаданные и историю из SQLite, но оставляет видеофайлы на диске.

## Команды

```bash
docker compose up -d --build
docker compose logs -f twitch-archive
docker compose ps
docker compose down
```

`docker compose down` не удаляет каталоги `data` и `recordings`, так как они подключены как bind mounts.

## API приложения

Документация FastAPI: `http://SERVER_IP:8080/docs`.
Основные маршруты: `/api/health`, `/api/settings`, `/api/status`, `/api/channels`, `/api/recordings`.

## Ограничения и правовые аспекты

Запись начинается после обнаружения трансляции очередным циклом мониторинга, поэтому фрагмент эфира до обнаружения не сохраняется. Сервис не восстанавливает пропущенные части, не скачивает скрытые или удалённые VOD, не обходит ограничения доступа и не получает доступ к приватным трансляциям. Используйте его только для публичного контента, на который у вас есть соответствующие права, соблюдая условия Twitch и применимое законодательство.

Первая версия не записывает чат. Мониторинг без Helix API не предоставляет подробные метаданные эфира.
