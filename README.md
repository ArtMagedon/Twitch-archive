# Twitch Archive — Podman edition

Сервис для мониторинга публичных Twitch-каналов и записи прямых эфиров. Проверка эфиров и запись выполняются через Streamlink; Twitch Helix API, Client ID и Client Secret не требуются.

## Возможности

- Мониторинг Twitch-каналов без регистрации приложения в Twitch Developer Console.
- Автоматическая запись обнаруженных публичных эфиров через Streamlink.
- Выбор качества потока: best, 1080p60, 1080p, 720p60, 720p, 480p, 360p или worst.
- Настраиваемый подкаталог и шаблон имени файла.
- Сохранение базы SQLite и видео в постоянных каталогах хоста.
- React + Vite frontend, FastAPI backend, SQLite.
- Контейнер собирается из `Containerfile` и запускается через Podman Compose.

Сейчас приложение развёртывается одним контейнером: API, мониторинг, запись и frontend. Это сохраняет простоту эксплуатации на текущем этапе. Границы будущих сервисов предусмотрены на уровне хранения и ответственности компонентов; преждевременно разносить их по контейнерам до появления очереди задач и межсервисного API не требуется.

## Требования

- Podman.
- Compose provider для Podman: обычно `podman-compose` или `docker-compose`, доступный через команду `podman compose`.
- Свободное место для видеоархива.

Проверить доступность Compose provider:

```bash
podman compose version
```

## Установка и запуск

```bash
git clone -b testNoAPI https://github.com/ArtMagedon/Twitch-archive.git
cd Twitch-archive
cp .env.example .env
```

Отредактируйте `.env`. Основные параметры:

```dotenv
APP_PORT=8080
RECORDINGS_HOST_DIR=./recordings
POLL_INTERVAL_SECONDS=60
STREAM_CHECK_TIMEOUT_SECONDS=25
STREAM_QUALITY=best
TZ=Europe/Bucharest
```

`RECORDINGS_HOST_DIR` — путь на хостовой системе, куда Podman будет монтировать каталог видео. `STREAM_QUALITY` задаёт начальное качество при первом запуске; после создания базы качество меняется в интерфейсе и хранится в SQLite. Можно задать абсолютный путь, например `/srv/twitch-archive/recordings`. Создайте его заранее и убедитесь, что пользователь, запускающий rootless Podman, имеет право записи.

Запуск и сборка:

```bash
podman compose up -d --build
podman compose ps
podman compose logs -f twitch-archive
```

После запуска откройте `http://localhost:8080` или `http://SERVER_IP:8080`. Документация API доступна по адресу `http://SERVER_IP:8080/docs`.

Остановка и обслуживание:

```bash
podman compose stop
podman compose start
podman compose restart
podman compose down
podman compose logs --tail=200 -f
```

`podman compose down` удаляет контейнеры, но не каталоги `data` и `recordings`, подключённые с хоста.

## Настройки записи

В интерфейсе откройте раздел «Настройки».

**Качество потока.** Выбирается один из вариантов Streamlink. Это не перекодирование в заданное разрешение: Twitch должен предоставлять соответствующий вариант качества. Если точного варианта нет, Streamlink может завершить запись с ошибкой.

**Каталог хранения.** Корневой каталог на хосте задаётся через `RECORDINGS_HOST_DIR` в `.env`. В интерфейсе можно задать подкаталог внутри него, например `streams/2026`. Изменение корневого каталога требует пересоздать контейнер:

```bash
podman compose down
# Изменить RECORDINGS_HOST_DIR в .env
podman compose up -d
```

**Шаблон имени.** Поддерживаются поля:

| Поле | Значение |
|---|---|
| `{channel}` | Логин канала |
| `{date}` | Дата начала записи, YYYY-MM-DD |
| `{time}` | Время начала записи, HH-MM-SS |
| `{title}` | Название трансляции |
| `{id}` | Идентификатор записи в базе |

Пример шаблона: `{date}_{time}_{channel}_{id}`. Расширение `.ts` добавляется автоматически. Недопустимые для имени файла символы заменяются на подчёркивания. Настройки применяются к новым записям; уже созданные файлы не переименовываются.

Исходные трансляции сохраняются в MPEG-TS (`.ts`) без перекодирования. MP4 и MKV не являются форматами прямой записи в текущей версии.

## Структура хранения

- `./data/archive.db` — база SQLite и настройки приложения.
- `RECORDINGS_HOST_DIR/<подкаталог>/<канал>/<YYYY-MM-DD>/` — исходные TS-файлы.

Архив не очищается автоматически. Удаление записи из интерфейса удаляет соответствующий файл. Удаление канала удаляет его метаданные и историю из SQLite, но не удаляет уже сохранённые видеофайлы.

## Архитектура дальнейшего развития

Будущие функции лучше реализовывать как отдельные сервисы, работающие с общей моделью медиафайлов:

1. **Notification Service** — получает события приложения (обнаружен эфир, началась/завершилась запись, ошибка конвертации) и отправляет уведомления. Источником событий станет внутренняя очередь или таблица событий, а не прямые вызовы из интерфейса.
2. **Media Converter** — отдельный worker на FFmpeg. Получает задачу на конвертацию TS в MP4 или MKV, сохраняет производный файл рядом с оригиналом либо в отдельном каталоге и записывает статус/метаданные результата. Оригинальный TS не удаляется автоматически.
3. **Built-in Player** — получает список доступных медиафайлов и воспроизводит поддерживаемые браузером форматы. Для TS потребуется либо серверная отдача через совместимый механизм, либо предварительная конвертация/трансмультиплексирование в формат, пригодный для браузерного воспроизведения.

В модели данных целесообразно разделять запись эфира (событие/сеанс), исходный файл и производные файлы. Тогда у одной записи может быть несколько медиа-артефактов: оригинальный TS, MP4, MKV, миниатюра и метаданные. Очередь задач конвертации и события уведомлений будут связаны с идентификатором записи, а не с конкретным путём файла. Эти сервисы пока не реализованы.

## Как работает мониторинг

Для каждого включённого канала приложение запускает короткую проверку через Streamlink. Если доступный поток найден, запускается отдельный процесс записи. Проверки выполняются последовательно, поэтому при большом количестве каналов полный цикл мониторинга может занимать заметное время.

Без Helix API сервис не получает полноценные метаданные Twitch: количество зрителей и часть информации о трансляции могут отсутствовать. Доступность публичных потоков зависит от текущего Twitch-плагина Streamlink; Twitch может менять механизмы доступа. Сервис не обходит ограничения доступа и не получает приватные трансляции.

## Ограничения и правовые аспекты

Запись начинается после обнаружения эфира очередным циклом мониторинга, поэтому фрагмент трансляции до обнаружения не сохраняется. Сервис не восстанавливает пропущенные части и не скачивает скрытые или удалённые VOD. Используйте его только для контента, на который у вас есть соответствующие права, соблюдая условия Twitch и применимое законодательство.

Первая версия не записывает чат. Мониторинг без Helix API не предоставляет подробные метаданные эфира.
